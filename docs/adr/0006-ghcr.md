# ADR 0006: GitHub Container Registry

**Status:** Accepted for Phase 1

## Decision
Publish Phase 1 build outputs to GitHub Container Registry using immutable digest references.

## Context
The platform needs a registry aligned with the initial GitHub ecosystem and Kubernetes pull workflows.

## Alternatives
Operate a production registry, use Docker Hub, or support every cloud registry initially. Each increases operations or integration scope.

## Security implications
Use short-lived least-privilege credentials, prevent credentials entering build layers, scan images, record digests, prefer signed provenance and restrict package visibility.

## Operational implications
Production requires GHCR permissions, retention policy, rate-limit handling and Kubernetes pull credentials. The local registry is only a development aid.

## Consequences
Initial registry integration is focused and low-operations, while customers are coupled to GHCR for Phase 1.

## Future extension points
Introduce a registry adapter for ECR, GCR, ACR and customer-managed registries.
